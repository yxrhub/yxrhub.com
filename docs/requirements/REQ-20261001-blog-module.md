## 1. 背景与动机

站点自 2026-06-23 立项以来已累积了相当数量的开发决策与踩坑经验，但它们**只存在于提交历史和 `docs/` 里**：

- `docs/ARCHITECTURE.md`、`docs/AI_DEV_WORKFLOW.md` 与 `docs/plans|requirements/` 是**写给协作者的说明文档**，面向"项目现在是什么样"，不记录"为什么走到这一步、当时踩了什么坑"；
- `git log` 有 16 次提交，但提交信息只有一行标题，**过程性知识（排障链路、备选方案取舍、失败尝试）没有任何载体**；
- 站点本身是"数字空间"的定位，却**没有任何持续产出的内容形态**——首页只有静态的自我介绍与项目卡片。

结果是：最有价值的那部分知识（例如"为什么不用迁移文件""为什么首页入口不能服务端渲染"）散落在 AI 会话里，一旦脱离上下文就失效；同时站点缺少一个能持续生长的模块。

## 2. 目标

在站点内建立 `blog` 模块，**以开发日志的形式把既有的开发过程沉淀成可公开阅读的文章**，并为后续持续写作提供一条低摩擦的路径。

## 3. 范围

### 3.1 本次要做(In Scope)

**内容基建**

- [ ] 建立 `blog` 内容集合，Markdown 落盘（`src/content/blog/*.md`），frontmatter 承载元数据
- [ ] 列表页 `/blog`：按年份分组，倒序（新的在前）
- [ ] 正文页 `/blog/<日期>-<短名>`：标题、日期、摘要、正文排版、上下篇导航
- [ ] 正文排版统一为一份共享样式，首页与博客共用

**站点入口**

- [ ] 顶部导航新增「日志」链接
- [ ] 首页新增「开发日志」区块（最新 3 篇 + 查看全部），位置在「项目」与「足迹」之间

**内容产出**

- [ ] 7 篇开发日志，按真实提交时间线覆盖 2026-06-23 至 2026-10-01 的开发历程
- [ ] 第 1 篇承担项目介绍、起步、目标与架构总览的职责

### 3.2 本次明确不做(Out of Scope)

- **标签与标签筛选页**（本次未选）
- **RSS 订阅**
- **草稿机制（`draft`）**——当前所有文章都可公开
- **站内搜索**、评论、点赞、阅读量统计
- **分页**——文章量级远未到需要分页的程度（列表页一次性渲染全部）
- **Markdown 语法高亮**——不做 Shiki 主题定制，沿用 Astro 默认
- **后台写文章**：不接入 `/admin`，写作仍走"仓库里新增 md 文件 + 提交"的路径
- **多语言**：本站内容以中文为主，不做 i18n 路由

## 4. 验收标准

**路由与内容**

- [ ] `/blog` 可访问，列出全部文章，按年份分组，年份与文章均倒序
- [ ] `/blog/<日期>-<短名>` 可访问，正文完整渲染，含标题、日期、摘要
- [ ] 文章底部有「上一篇 / 下一篇」导航，指向按时间排序的相邻文章；首篇无「上一篇」、末篇无「下一篇」
- [ ] 不存在的 slug 返回 404
- [ ] 新增一篇 md 文件后，无需改动任何 `.astro` 代码即可出现在列表页并可通过 URL 访问

**入口**

- [ ] 顶部导航出现「日志」，点击进入 `/blog`
- [ ] 首页出现「开发日志」区块，展示最新 3 篇，含「查看全部」链接
- [ ] 首页其余区块（关于 / 项目 / 足迹）内容与视觉**无回归**

**渲染质量**

- [ ] 明、暗两种配色下正文均清晰可读，不出现浅底浅字
- [ ] 代码块、引用、列表、表格、分隔线在正文中有明确样式（不依赖浏览器默认）
- [ ] 窄屏（≤640px）下列表页与正文页无横向溢出

**工程约束**

- [ ] `pnpm build` 通过
- [ ] 博客为公开内容，**保持预渲染**（静态 HTML）；不触碰中间件的 `isPrerendered` 短路分支
- [ ] 未引入新的运行时依赖

## 5. 约束与依赖

| 类型 | 说明 |
| --- | --- |
| 技术约束 | 使用 Astro 7 的 **Content Layer API**（`src/content.config.ts` + `glob()` loader）。仓库尚无该文件；既有 `src/content/index.md` 是**原始 md 模块导入**（`import * as doc from "../content/index.md"`），与内容集合机制互不干扰，**不要动它** |
| 技术约束 | 博客页为公开内容，**应保持预渲染**。注意：预渲染页会跳过中间件的 `isPrerendered` 短路之后的逻辑，因此**不要在这些页面上依赖 `Astro.locals.user`**（AGENTS.md 红线 10） |
| 技术约束 | 视觉必须沿用 `Layout.astro` 的设计令牌，**组件内禁止硬编码颜色**，否则深色模式失效 |
| 兼容性 | 纯新增路由与内容，不修改任何现有页面的 URL，不影响认证链路与 `/admin` |
| 内容风险 | 文章会公开披露站点的实现细节与踩坑过程。**不写入任何密钥、真实连接串、内网地址与个人隐私信息**（如具体邮箱）；需要提及凭据时一律脱敏 |
| 外部依赖 | 无新增依赖、无新增环境变量 |

## 6. 已确认的决策

- [x] **文章级 URL 结构** → `/blog/<YYYY-MM-DD>-<短名>`，如 `/blog/2026-06-24-project-kickoff`。
  理由：这是**开发日志**，日期是文章身份的一部分；扁平一层路由，URL 肉眼可读、可手抄、对搜索引擎友好。
  **不采用**纯随机 ID（如 `/blog/20261001-a1b2c3d4`）——不可读、不可猜、分享出去没有信息量。
- [x] **站点入口** → 顶部导航加「日志」**且**首页新增独立区块（两者都要）。
- [x] **配套能力** → 只做「按年分组列表 + 上下篇导航」；**不做**标签、RSS、草稿开关。

## 7. 补充说明

- 文章 slug 与文件名一致（去掉 `.md`），文件名即 `YYYY-MM-DD-<短名>.md`，**排序键是 frontmatter 的 `date`**，因此改文件名不影响排序。
- 同一日期多篇文章时，以文件名字典序**倒序**作为稳定的次序兜底，既保证「上一篇 / 下一篇」不出现随机顺序，也让同日几篇读起来同样符合「新的在前」。
- 首页「开发日志」区块的标题与简介写入 `src/content/index.md` 的 frontmatter，**保持首页内容契约的单一数据源**（见 `ARCHITECTURE.md` 第 5.5 节）。
