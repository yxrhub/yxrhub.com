## 1. 方案概述

不引入任何 UI 框架,以 **CSS 变量设计令牌 + Astro 组件 scoped 样式** 重建视觉系统;把内容中两处结构化清单(3 个项目、7 个平台链接)提升为 **Markdown frontmatter 数据**,由组件渲染为卡片与链接网格。正文散文仍保留在 Markdown 中,维持「内容 / 视图分离」原则。

## 2. 候选方案与取舍

| 方案 | 做法 | 优点 | 缺点 | 采用 |
| --- | --- | --- | --- | --- |
| A | 纯 CSS,靠 `:has()` 选择器把现有嵌套列表样式化成卡片 | 完全不动内容文件 | 依赖 `:has()` 后代结构,内容一改样式即失效;且无法从「状态：」文本中提取徽章 | ❌ |
| B | **frontmatter 存结构化数据 + 组件渲染卡片,散文留在 Markdown 正文** | 结构显式、健壮;卡片/网格渲染干净;文案一字不改 | 内容文件结构有较大调整 | ✅ |
| C | 完整 Content Collections + schema 校验 | 类型最严谨 | 超出本次范围(REQ 已列为 Out of Scope),改动面过大 | ❌ |

**选择理由**:方案 A 的样式与内容结构耦合过紧,属于技术债;B 在可控改动内同时拿到健壮性与最佳视觉结果。

## 6. 风险与降级

| 风险 | 可能性 | 影响 | 应对 / 降级 |
| --- | --- | --- | --- |
| frontmatter YAML 解析失败导致构建中断 | 低 | 高 | 构建后立即以 `pnpm build` 校验 |
| `:global()` 选择器作用域写错,样式不生效 | 中 | 中 | 本地预览逐元素核对 |

| 深色模式下品牌渐变对比度不足 | 中 | 低 | 深色模式改用亮色阶强调色 |

## 7. 回滚方案

全部改动均为呈现层与内容结构,不涉及数据与外部状态。回退方式:

```bash
git checkout -- src/                  # 单文件回滚
git revert <本次提交>                  # 整体回滚
```

由于未提交前可随时 `git restore`,风险完全可控。
